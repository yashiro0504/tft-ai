### R1. `unit` 필터가 메모이즈된 응답 객체를 직접 변조 🔴

**문제**

`getStats()`는 DB 응답을 모듈 메모리 `memo`(TTL 5분)에 **객체 참조 그대로** 저장하는데,
라우트가 `res.rows = ...`로 그 객체를 수정한다. 첫 `unit_item&unit=` 요청 한 번으로
캐시가 해당 기물 조합만 남은 상태로 오염된다.

**근거**

```ts
// lib/tftStats.ts:58-65
const memo = new Map<string, { value: unknown; expiresAt: number }>()
async function memoized<T>(key: string, fn: () => Promise<T>, keep: (v: T) => boolean): Promise<T> {
  const hit = memo.get(key)
  if (hit && hit.expiresAt > Date.now()) return hit.value as T   // 같은 참조 반환
  const value = await fn()
  if (keep(value)) memo.set(key, { value, expiresAt: Date.now() + MEMO_TTL_MS })
  return value
}
```

```ts
// app/api/tft/stats/route.ts:28-33
const res = await getStats(type, parseStatFilter(params))
const unit = params.get('unit')
if (type === 'unit_item' && unit) {
  const u = unit.toLowerCase()
  res.rows = res.rows.filter((r) => 'champKey' in r && r.champKey.toLowerCase() === u)  // 캐시 변조
}
```

**영향**

- 이후 5분간 같은 워커의 `GET /api/tft/stats?type=unit_item`(unit 없음)이 필터된 행만 반환
  → `/meta` BIS 탭 누락·오염.
- 같은 프로세스의 `buildMetaFacts()`(`lib/llm.ts:565`)도 같은 캐시를 읽으므로
  **AI 프롬프트 [메타 실측 통계]의 BIS TOP8이 오염**된다.
- `Cache-Control: s-maxage=600` 때문에 CDN이 오염 응답을 최대 10분 배포할 수 있다.

**수정 지시**

1. `app/api/tft/stats/route.ts`에서 원본을 절대 수정하지 말고 새 객체를 만든다.

```ts
const res = await getStats(type, parseStatFilter(params))
const unit = params.get('unit')?.toLowerCase()
const payload =
  type === 'unit_item' && unit
    ? { ...res, rows: res.rows.filter((r) => 'champKey' in r && r.champKey.toLowerCase() === unit) }
    : res
return NextResponse.json(payload, { headers: STATS_CACHE_HEADERS })
```

2. 재발 방지를 위해 필터 로직을 순수 함수로 분리한다(권장 위치: `lib/statsShared.ts`).

```ts
export function filterStatsByUnit<T extends StatRow>(res: StatsResponse<T>, unit: string): StatsResponse<T> {
  const u = unit.toLowerCase()
  return { ...res, rows: res.rows.filter((r) => 'champKey' in r && r.champKey.toLowerCase() === u) }
}
```

3. **회귀 테스트 추가**: `scripts/testRollup.js`의 "서빙 (lib/tftStats)" 구간에
   - `filterStatsByUnit(res, 'ahri')` 호출 후 `res.rows.length`가 변하지 않았는지
   - 반환 객체가 원본과 다른 참조인지
   를 확인하는 케이스를 넣는다. PGlite가 없어도 순수 함수 테스트는 항상 실행돼야 한다.

**완료 조건**

- [ ] `filterStatsByUnit`가 원본 `res.rows`를 변경하지 않는다는 테스트가 CI에서 실행됨
- [ ] `npx eslint app/api/tft/stats/route.ts lib/statsShared.ts` 통과
- [ ] `npm run typecheck` 통과

### R2. 집계 실패 시에도 원본을 prune 해 데이터 유실 가능 🟠

**문제**

`main()`은 집계 갱신 결과(`aggregates.error`)와 무관하게 `store.prune()`을 호출한다.
0006 미적용·RPC 오류 상태에서 패치가 바뀌면, **집계가 한 번도 계산되지 않은 원본 보드가 삭제**된다.
(집계는 영구 보관이지만, 그 전에 계산되지 않았다면 원본이 사라져 복구할 수 없다.)

**근거**

```ts

// 5) 원본 정리
const removed = await store.prune(CFG.keepPatches)
```

**수정 지시**

집계가 실패하면 prune을 건너뛰고 다음 실행에서 재시도한다.

```ts
if (aggregates?.error) {

```

**테스트 추가**

  (집계 오류가 있으면 `false`).
- 통합 흐름까지 보려면 `scripts/testCollect.js` (`process.argv.push('--dry-run')` 사용 중)에서
  `require('./collect/store')`의 `createMemoryStore`를 `refreshRollup`이 throw하는 저장소를

  `store._state.matches.size`가 줄지 않았는지 확인한다.
  (collectDb가 require 시점에 팩토리를 구조 분해하므로 **require 전에** 패치해야 한다.)

**완료 조건**

- [ ] 집계 실패 시 `prune` 미호출 테스트 통과

### R3. 덱 클러스터 재빌드가 데드라인에 굶어 영구 지연 가능 🟠

**문제**

수집 루프가 `deadline`까지 돌면, 이어지는 `refreshAggregates`에서
`deadline - Date.now() > DECK_JOB_MIN_MS`가 항상 false가 되어 `rebuildComps`가 계속 미뤄진다.
`daily` 조건은 참인데도 매 실행 미뤄지면 `/api/tft/decks`가 오래된 덱을 계속 서빙한다.

**근거**

```ts
// scripts/collectDb.js:140-154
const daily = force || Date.now() - compsAt > CFG.deckRefreshHours * 60 * 60 * 1000
...
if (daily && out.latestPatch) {
  if (force || deadline - Date.now() > DECK_JOB_MIN_MS) out.comps = await rebuildComps(...)
  else log.log('  덱 클러스터: 남은 시간이 부족해 다음 실행으로 미룸')
}
```

**수정 지시 (택 1)**

- **A안(권장)**: 수집 시드 루프의 종료 기준을 `deadline`이 아니라
  `deadline - DECK_JOB_MIN_MS`로 두고, 덱 재빌드 몫을 항상 남긴다.
  `refreshAggregates`의 `deadline` 인자도 동일한 값을 유지.
- **B안**: 덱 클러스터 전용 워크플로/스크립트(`collect:db:rollup`)를 매일 1회 별도 실행하고,
  수집 워크플로에서는 제거한다.
- 어느 쪽이든 **미뤘을 때 `tft_collect_runs.note`에 남기고**, 24시간 이상 갱신이 없으면
  경고 로그(또는 `/api/health` 경고)를 남긴다.

**완료 조건**

- [ ] `refreshAggregates`(또는 `collectionDeadline()`)에 `now`를 주입할 수 있게 해,
      "수집이 maxMinutes를 소진한" 시나리오에서도 덱 재빌드가 실행되거나 별도 잡으로 분리됨을 테스트로 고정
- [ ] `stat_comp`의 `max(updated_at)`이 24시간 이상 오래되면 경고가 남는 경로 존재

### R5. DB 장애 시 네거티브 캐시 부재 🟡

**문제**

`memoized`는 `source === 'db'`인 값만 캐시한다. DB가 죽으면 `/api/tft/stats`(120req/min)와
`/api/tft/decks`(60req/min)의 요청마다 `STATS_DB_TIMEOUT_MS`(기본 3초)를 기다린 뒤 JSON으로 폴백한다.
장애 중 지연이 그대로 사용자에게 전파되고, Supabase에도 불필요한 연결이 쌓인다.

**수정 지시**

- 실패 결과를 **15~30초** 정도만 캐시하는 `negativeMemo`를 추가한다.
  키는 `stats:*`/`decks:*`/`filters` 단위로 하고, TTL이 지나면 즉시 재시도한다.
- `fallbackReason`은 그대로 유지한다(운영에서 원인 구분 가능해야 함).
- 값이 아니라 **실패 시각**만 저장해, 복구되면 다음 요청에서 바로 DB를 다시 시도하게 한다.

```ts
const failMemo = new Map<string, number>() // key → retryAfterMs
const FAIL_TTL_MS = 20_000
```

**완료 조건**

- [ ] DB 타임아웃 2회 연속 시 두 번째 요청은 즉시 폴백(로그 `ms`가 수 ms)
- [ ] `fallbackReason`/`source` 응답 스키마 변화 없음

### R6. `?unit=` 이 원본 키 완전 일치라 문서화된 슬러그 입력이 동작하지 않음 🟡

**문제**

`/api/tft/stats?type=unit_item&unit=`는 `champKey.toLowerCase()`와 **완전 일치**만 비교한다.
DB 키는 `statChampKey('DA_18_Ahri')` → `'Ahri'`이고, `Lux`처럼 원본 id가 `DA_Lux18_Base`이면
키가 `'Lux18_Base'`가 된다. 반면 문서는 BIS 용도로 슬러그(`ahri`, `lux`)를 쓰는 것처럼 읽힌다.
또한 필터 후에도 `totalBoards`/`filter`는 그대로라 클라이언트가 오해할 수 있다.

**근거**

- `docs/DATA-PLATFORM.md:259` — `GET /api/tft/stats?type=unit_item&unit=` "기물별 아이템 추천 (BIS)"
- `lib/entitySlug.ts:29-36` — 화면 슬러그는 접두사·세트 꼬리를 제거한 소문자

### R7. `getEntityPage`의 이중 `decodeURIComponent` → 500 가능 🟡

**문제**

Next.js는 동적 세그먼트 `params.slug`를 이미 디코딩해 전달한다. 여기서 한 번 더 디코딩하므로
슬러그에 `%`가 포함된 요청(예: `/champions/a%25b` → `a%b`)에서 `URIError`가 발생해 500이 된다.
같은 저장소의 `app/profile/[region]/[name]/[tag]/opengraph-image.tsx:12-18`은 try/catch로 방어한다.

**근거**

```ts
// lib/entityData.ts:309-315
export const getEntityPage = cache(async (kind: EntityKind, slug: string) => {
  const s = decodeURIComponent(slug).toLowerCase()   // ← 여기서 throw 가능
  if (!/^[a-z0-9]{1,60}$/.test(s)) return null
  ...
})
```

**수정 지시**

```ts
function safeDecode(value: string): string {
  try {
    return decodeURIComponent(value)
  } catch {
    return value
  }
}
```

- `getEntityPage`에서 `safeDecode(slug)` 사용.
- `notFound()`로 끝나야 하는 입력은 500이 아니라 404가 되게 한다.

**완료 조건**

- [ ] `/champions/a%25b` 요청이 500이 아니라 404(또는 정상 페이지)로 응답
- [ ] 기존 정상 슬러그 페이지 회귀 없음(빌드/`next start` 스모크)

## 4. 회귀 금지 목록 (이번 리뷰에서 정상 확인됨)

아래 동작은 의도된 설계이므로 수정 과정에서 깨지면 안 된다.

- **집계 공식**: 기물 1개당 1건, 아이템은 기물이 든 아이템 1개당 1건, 시너지는 활성(tier>0)만.
  `star=0`/`tier=0`은 합계 행.
- **KST 날짜**: `game_date`는 KST 기준, `days=7`은 오늘 포함 7일.
- **티어 누적**: `master` = 챌린저+그마+마스터, `diamond` = +다이아.
- **표본 규칙**: 기물·아이템·시너지 30, 기물×아이템 20, 덱 15 미만은 `lowSample`.
- **표준오차**: `2.29 / √n`, 소수 2자리.
- **폴백 계약**: DB를 못 쓰면 `source: 'json'`, `filter: null`, `fallbackReason` 유지.
- **프라이버시**: 원본 테이블에 닉네임/Tag/PUUID 없음, 시드는 HMAC+AES-GCM, anon은 집계 SELECT만.
- **캐시 키**: 분석/인트로/overview 키에 `COACH_PROMPT_VERSION` + `SCORING_VERSION` 포함.
- **SSE**: 15초 하트비트, `no-transform`, 클라이언트 종료 시 LLM 스트림 abort.
