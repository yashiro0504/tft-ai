# 규칙 검증 · 게임 사실 탐지

2026-10-22 · 쌓인 랭크 보드로 코칭 규칙과 게임 사실을 확인한다. 모델 학습이 아니라 **규칙을 데이터로 검증하는 일**이다.
같은 날 두 번의 오진단('1성 4·5코 캐리 + 아이템 = 나쁨', 장로 드래곤 2칸 미반영)이 모두 규칙을 짐작으로 넣어서 생겼다.

| 명령 | 하는 일 |
| --- | --- |
| `npm run rules:check` | 장면 규칙(lib/keyMoments 실제 코드)이 뜬 보드가 **같은 레벨 보드보다** 실제로 등수가 나쁜지 잰다. 코스트·개수 기준을 바꾼 탐침도 함께 |
| `npm run facts:detect` | ① 2칸 기물 후보 ② 시너지 인원 이상(2명 계산·사전 누락) ③ 2성·아이템이 한 번도 없는 기물 ④ 코스트표·이름·단계표 누락 |

공통 옵션: `--source=db|ladder|fixtures` (기본: DB 시크릿 있으면 db → `data/ladderBoards.json` → 골든셋) · `--patch=16.20` · `--max-matches=3000` · `--out=파일.md` · `--strict` (문제 있으면 종료 코드 1).

- 자동 실행: `.github/workflows/rules-check.yml` 매일 11:45 KST. Riot 호출 없이 DB 만 읽으므로 **개발 키로도 충분**하다. 결과는 Actions 실행 요약 · 노란 경고 주석 · `rules-report` 아티팩트.
- 판정: 같은 레벨 보드끼리의 평균 등수 차이(+ = 장면이 뜬 보드가 나쁨). |차이| ≥ 0.25 이고 95% 구간이 0을 넘으면 `✓ 근거 있음` / `✗ 반대`, 해당 보드 30개 미만은 `표본 부족`.
- `sameComp` 는 정의상 1등 보드에서 뜰 수 없어 1등을 빼고 비교한다 — 그래도 편향이 남으니 참고만.
- 탐지 결과는 **확인할 목록**이다. 코드는 자동으로 고치지 않는다. 확인 후 `lib/boardSlots` · `lib/constants` · `lib/championTraits.json` · `lib/traitBreakpoints.json` 에 반영하고, 이미 아는 시너지 2명 계산은 `scripts/detectGameFacts.js` `KNOWN_TRAIT_DOUBLE` 에 적는다.
