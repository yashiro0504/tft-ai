# 경기 경과 시간 ("N분 전 / N시간 전 / N일 전") 계산 기준

코드: `lib/timeAgo.ts` `formatTimeAgo` · 테스트: `scripts/testMatchIntegrity.js` (경과 시간)

## 기준

- **기준 시각:** 경기 종료 시각 = Riot 매치 `info.game_datetime`(ms). 캐시·응답에는 이 값만 두고 문자열은 두지 않는다. 화면(`TimeAgo`)이 1분마다 현재 시각으로 다시 계산한다.
- **계산:** `지금 − 종료 시각`의 타임스탬프 차이만 쓴다. 달력 날짜·시간대(KST/UTC)는 보지 않는다.
- **단위와 반올림:** 각 단위는 반올림한다. 경계는 moment.js / dayjs `fromNow`와 같다.

| 차이 (반올림) | 표시 |
| --- | --- |
| 44분까지 | N분 전 (최소 1분) |
| 45분 ~ 21시간 | N시간 전 (반올림한 시간) |
| 22시간부터 | N일 전 (반올림한 일, 최소 1일) |

예: 10.26 02:30 KST에 끝난 경기는 10.28 12:43에는 2.43일이라 "2일 전", 16:00에는 2.56일이라 "3일 전"이다.

## 왜 반올림인가 (2026-10-28 16시 재확인)

24시간 단위 **내림**으로 계산하던 때, 빈 틈#123의 10판이 12:43에는 lolchess와 같았고 16:00에는 모두 하루 적었다. 10판이 새벽 몇 시간 안에 몰려 있었는데, 그 사이에 경과 일수의 소수점이 0.5를 넘었다. 달력 날짜 기준은 같은 날 12:43과 16:00 사이에 바뀌지 않으므로 이 패턴을 설명하지 못하고, 반올림은 설명한다.

lolchess의 계산식은 공개돼 있지 않다. 반올림은 이 관찰에서 추정한 것이다.

## ±1 차이가 남을 수 있는 경우

- **x.5일 경계 몇 분 안:** 화면은 1분마다 다시 그리고, lolchess는 페이지를 연 시각에 고정될 수 있다. 같은 순간에 보지 않으면 하루 차이가 날 수 있다.
- **종료 시각이 아닌 시작 시각을 쓰는 경우:** 경기 길이(30~40분)만큼 차이가 난다. x.5일 경계 근처에서만 하루가 갈린다.
- **25일이 넘은 경기:** dayjs는 "한 달 전"으로 바꾸지만, 여기서는 계속 "N일 전"이다.

검증할 때는 같은 시각에 두 화면을 열고, 일 수가 다르면 그 경기의 경과 시간이 x.5일 근처인지 확인한다.
