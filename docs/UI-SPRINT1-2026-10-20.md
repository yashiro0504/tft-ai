## 2. 상세 지시

### S1. DB 덱 상세 페이지 (U1) — P0 버그 🐞

**문제 재확인**

- `MetaDashboard.tsx:767-776`은 DB 덱에도 `/deck/${id}` 링크·공유를 노출
- `app/deck/[id]/page.tsx:22-24`는 `lib/decksData.json`만 조회
  → DB-only id는 **404**, JSON과 id가 겹치면 **다른 패치·수치의 JSON 덱** 표시

**1) `lib/tftStats.ts`에 단일 덱 조회 추가**

```ts
export interface ResolvedDeck {
  deck: DeckView              // deckViewsFromRaw([row.deck])[0]
  patch: string
  tierMin: TierFilter
  updatedAt?: string
}
export async function getDeckById(
  id: string,
  opts: { patch?: string | null; tier?: TierFilter } = {}
): Promise<ResolvedDeck | null>
```

- `db()`가 null이면 `null` 반환(JSON 폴백은 페이지가 처리).
- Supabase 조회(anon, `stat_comp`는 공개 select):

```ts
let q = c.from('stat_comp').select('deck, patch, tier_min, updated_at').eq('comp_id', id)
if (opts.patch) q = q.eq('patch', opts.patch)
if (opts.tier) q = q.eq('tier_min', tierArg(opts.tier))
const rows = await withTimeout(q.abortSignal(signal))   // 기존 withTimeout 재사용
```

- 선택 규칙:
  1. `opts.patch`가 있으면 그 패치만.
  2. 없으면 **숫자 비교로 최신 패치** 선택 (`'16.9' > '16.20'` 문자열 비교 금지).
  3. 같은 패치에 여러 `tier_min`이 있으면 `opts.tier` → 없으면 `MASTER` → `GRANDMASTER` → `CHALLENGER` → `DIAMOND` 순.
  4. `updated_at` 최신 행 우선.
- 반환: `deckViewsFromRaw([row.deck])[0]` (이미 export됨), 패치/티어/업데이트 시각.
- 실패(타임아웃·RLS·malformed)는 `null` + `logEvent('warn', 'deck_by_id_failed', ...)`.

**2) `/deck/[id]`가 JSON → DB를 해석하도록 변경**

```tsx
const resolveDeck = cache(async (id, patch, tier) => {
  // patch/tier 쿼리가 있으면 DB 우선 (DB 덱의 현재 수치)
  if (patch || tier) {
    const db = await getDeckById(id, { patch, tier })
    if (db) return { ...db, source: 'db' as const }
  }
  const json = getDeckViews().find((d) => d.id === id)
  if (json) return { deck: json, patch: null, tierMin: null, source: 'json' as const }
  const db = await getDeckById(id, { patch, tier })   // DB-only id
  return db ? { ...db, source: 'db' as const } : null
})
```

- `generateStaticParams()`는 기존 JSON 목록 유지(빌드 시 DB 호출 없음).
- `generateMetadata`와 본문이 **같은 resolveDeck** 사용(React `cache`로 요청 내 중복 제거).
- `searchParams`(Promise)에서 `patch`/`tier`를 읽고 검증:
  - patch: `/^\d{1,2}\.\d{1,2}$/`
  - tier: `TIER_FILTER_OPTIONS`의 id만.
- 헤더 표시:
  - DB: `패치 {patch} · {tierLabel} 집계` + "DB 집계" 칩
  - JSON: 기존 `getDeckMetaInfo().patch` 유지
- `ShareButton` 경로: DB면 `/deck/{id}?patch={patch}&tier={tier}`.
- canonical: query가 있으면 그 query 포함, 없으면 `/deck/{id}`.
- 없는 id는 기존처럼 `notFound()`, metadata는 noindex.

**3) 링크 생성 쪽 수정**

- `MetaDashboard.tsx`의 `DeckDetail`:
  - DB 모드(`dbMode && !fellBack`)면 `/deck/${id}?patch=${appliedPatch}&tier=${filter.tier}`.
  - JSON이면 기존 `/deck/${id}`.
- `lib/entityData.ts`의 `EntityDeck`에 `patch?: string`, `tier?: TierFilter` 추가,
  `getDecks`가 돌려준 `filter.patch`/`tier`를 채운다.
- **R8에서 `linkable: false`로 막았던 DB 덱을 다시 링크 가능**하게 바꾼다
  (S1이 해석하므로 404가 나지 않는다). `scripts/testRollup.js`의 R8 기대값도
  `fromDb === true && linkable === true`로 갱신한다.
- `lib/entityData.ts`의 덱 링크 href도 query를 포함한다.

**4) 테스트**

- `scripts/testRollup.js`의 PGlite `apiChecks`에 추가:
  - `getDeckById(sampleDeck.id, { patch: '16.20', tier: 'master' })` → deck id 일치, `patch/tierMin` 반환
  - 존재하지 않는 id → `null`
  - `db` 미설정/타임아웃 → `null` (예외를 밖으로 던지지 않음)
  - (가능하면) 같은 comp_id를 다른 패치에 넣고 최신 패치가 선택되는지
- JSON 경로는 `testRollup.js`의 기존 엔티티 테스트에서 `linkable === true`로 확인.

**완료 조건**

- [ ] DB-only 덱 id `/deck/<id>` → 200, 올바른 패치·티어 수치
- [ ] JSON과 id가 겹치는 경우 `?patch=&tier=`로 DB 덱이 정확히 표시
- [ ] 없는 id → 404 + noindex
- [ ] 메타 대시보드·엔티티 페이지의 덱 링크/공유가 404를 만들지 않음
- [ ] R8 테스트가 새 동작(DB 덱 링크 허용)에 맞게 갱신되고 통과

### S2. 메타 필터·탭 URL 동기화 (U2) — P1 퀵윈 🔗

**문제**

패치·티어·기간·탭이 `useState`에만 있어 새로고침/공유/뒤로가기에서 초기화된다.

**1) Suspense 경계 추가 (Next 15 필수)**

`useSearchParams()`를 client component에서 쓰면 정적 페이지(`/meta`)가 CSR bailout 될 수 있다.
`app/meta/page.tsx`에서 `MetaRanking`을 `<Suspense>`로 감싼다.

```tsx
import { Suspense } from 'react'
...
<Suspense fallback={<div className="rk-skeleton" aria-hidden="true" />}>
  <MetaRanking ... />
</Suspense>
```

**2) 초기값을 URL에서 읽기**

`app/components/MetaDashboard.tsx`:

- `useSearchParams`, `useRouter`, `usePathname` import.
- 초기 `filter`/`tab`은 URL → 검증(`parseStatFilter`) → 없으면 현재 기본값.
- 탭은 `TABS`의 id만 허용.

```ts
const sp = useSearchParams()
// ReadonlyURLSearchParams → URLSearchParams 로 변환 (parseStatFilter 타입 맞춤)
const initialFromUrl = parseStatFilter(new URLSearchParams(sp.toString()))
const initialTab = TABS.some((t) => t.id === sp.get('tab')) ? sp.get('tab') as TabId : 'decks'
```

**3) 상태 → URL 동기화**

- `filter`/`tab` 변경 시 `router.replace(`${pathname}?${qs}`, { scroll: false })`.
- **기본값은 파라미터 생략**(`patch` 최신, `tier=master`, `days=7`, `tab=decks`).
- 이미 같은 query면 replace하지 않는다(루프 방지).
- `useEffect` 의존성은 `filter.patch`, `filter.tier`, `filter.days`, `tab`.

**4) URL → 상태 (뒤로가기/앞으로가기)**

- `searchParams` 변경 시 URL 값을 state에 반영한다.
- state→URL effect와 충돌하지 않게 **마지막으로 적용한 query 문자열을 ref에 저장**하고,
  같으면 setState/replace를 모두 건너뛴다.

**5) 중복 fetch 방지**

- 기존 `loadedRef`(decks/sections key)의 초기값을 **URL에서 복원한 필터 키**로 맞춘다.
- 서버 SSR이 기본 필터 데이터를 이미 내려준 경우, URL 필터가 기본과 같으면 fetch하지 않는다.
- `useEffect(() => { if (dbMode) void loadFiltered(tab, filter) }, [dbMode, tab, filter])`는 유지하되
  `loadedRef` 비교로 1회만 요청되는지 확인한다.

**테스트/확인**

- `/meta?patch=16.20&tier=challenger&days=3` 진입 → 해당 필터로 1회 로드
- 필터 변경 → 새로고침/복사/뒤로가기 → 동일 상태
- 기본값 → URL에 `?patch=&tier=&days=`가 남지 않음
- 네트워크 탭에서 중복 요청 없음

**완료 조건**

- [ ] URL 공유·새로고침·뒤로가기에서 필터/탭 유지
- [ ] 기본 URL이 깔끔하고, 잘못된 값은 기본값으로 안전하게 복원
- [ ] `/meta`가 여전히 정적/ISR로 빌드되고 `npm run build` 통과

### S3. 경기 카드 기물 → 챔피언 상세 링크 (U6) — P2 작은 기능 🔗

**데이터 제약 (중요)**

- 기물: `SlimMatchUnit.id`(예: `DA_18_Ahri`)가 있어 `entityHref('champion', id)` 사용 가능.
- 아이템: `SlimMatchUnit.items`는 **한글 이름 배열** → 슬러그 직접 생성 불가.
- 시너지: `SlimMatchTrait.name`도 한글 이름만.

**1차 구현 (기물만)**

`app/components/MatchCard.tsx`의 기물 아이콘/이름 영역(현재 `div`, 238~303행 부근)을
`Link`로 감싼다.

```tsx
import Link from 'next/link'
import { entityHref } from '@/lib/entitySlug'
...
<Link
  href={entityHref('champion', unit.id)}
  onClick={(e) => e.stopPropagation()}
  aria-label={`${unit.name} 챔피언 통계 보기`}
  className="..."
>
  {/* 기존 아이콘/별/이름 */}
</Link>
```

- 카드 자체에 펼침/선택 onClick이 있으면 `stopPropagation` 필수.
- 아이콘 단위로만 링크하고, 카드 전체를 링크로 만들지 않는다(모바일 오탭 방지).
- `unit.id`가 비어 있는 데이터는 링크하지 않는다(조건부 렌더).

**(선택) 2차 — 아이템·시너지**

- `lib/entityLookup.ts`에서 `tftData.itemMap`/`traitMap`을 **이름→키 역인덱스**로 만든다.
- 동명 충돌(상징/변형)은 `null` 반환 → 링크 생략.
- 유닛 테스트로 모호성 케이스를 고정한다.

## 5. 결정 필요 / 주의

- **S1의 기본 해석 순서**: `?patch`/`?tier`가 있으면 DB 우선, 없으면 JSON 우선으로 두었다.
  기존 정적 JSON 덱 페이지의 수치를 유지하면서 DB-only 덱 404를 없애기 위한 절충이다.
  "항상 DB 우선"으로 바꾸려면 빌드 시 DB 접근 횟수(JSON 덱 59개)와 ISR 비용을 먼저 측정한다.
- **S1 canonical**: query를 canonical에 포함할지 여부. 검색 중복을 피하려면
  `/deck/{id}`를 canonical로 두고 query는 표시용으로만 쓰는 방법도 있다.
- **S2 `useSearchParams`**: Suspense 누락 시 빌드가 실패할 수 있으니 반드시 `app/meta/page.tsx`에 경계를 둔다.
- **S3 아이템/시너지**: 이름→키 리졸버 없이 추측 링크를 만들지 않는다(404/오링크 방지).
- 이번 스프린트에서 **U3(추세)·U4(탐색기)·U5(sitemap)** 는 건드리지 않는다.
